# DocuMate

종이 서류를 찍으면 AI가 자동으로 문서 종류를 분류하고, 핵심 정보를 추출하며, 소비 패턴까지 분석해주는 지능형 문서 관리 플랫폼입니다.

## 1. 프로젝트 개요

### 프로젝트명
DocuMate

### 한 줄 소개
종이 서류와 영수증을 AI로 정리하고, 만료일 알림과 소비 분석까지 제공하는 문서 관리 서비스

### 타겟 사용자
- 종이 계약서, 보증서, 처방전, 영수증 등을 자주 보관해야 하는 개인 사용자
- 문서 분실, 훼손, 기한 누락을 줄이고 싶은 사용자
- 영수증 기반 소비 내역을 쉽게 관리하고 싶은 사용자

### 기획 배경
일본의 아날로그 문서 문화에서는 계약서, 보증서, 처방전, 영수증 등 종이 서류를 직접 보관해야 하는 경우가 많습니다.  
이로 인해 문서 분실, 훼손, 갱신일 및 만료일 누락 문제가 발생할 수 있습니다.  
DocuMate는 이러한 문제를 AI 기반 문서 정리, 디지털 보관, 알림, 소비 분석 기능으로 해결하는 것을 목표로 합니다.

## 2. 핵심 컨셉

DocuMate의 핵심 흐름은 다음과 같습니다.

```txt
이미지 업로드 또는 모바일 카메라 촬영
↓
OCR 및 AI 문서 분석
↓
문서 종류 자동 분류
↓
일반 문서 → 디지털 캐비닛
영수증 → 영수증 관리
↓
만료일 알림 / 소비 리포트 / Pro 기능 제공
```

## 4. 핵심 기능

### 4.1 스마트 업로드

사용자가 문서 이미지 파일을 업로드하면 AI 분석이 자동으로 시작됩니다.

주요 기능:
- Web 환경에서는 JPG / PNG 이미지 파일 업로드
- Mobile App 환경에서는 카메라를 직접 실행하여 촬영한 사진 파일 사용 가능
- PDF는 업로드 형식에서 제외
- 파일 용량은 장당 최대 10MB
- 한 번에 최대 10장 업로드
- 업로드 후 AI 분석 상태 표시
- 분석 완료 후 문서 종류에 따라 저장 위치 분기

업로드 처리 흐름:

```txt
JPG / PNG 업로드 또는 모바일 카메라 촬영
↓
S3 원본 이미지 저장
↓
OCR 분석
↓
AI 문서 분류
↓
일반 문서: 디지털 캐비닛에 저장
영수증: 영수증 관리 페이지에서 별도 관리
```

예외 처리:
- 지원하지 않는 형식일 경우 오류 메시지 표시
- 파일 용량이 10MB를 초과할 경우 오류 메시지 표시
- 업로드 수량이 제한을 초과할 경우 오류 메시지 표시
- 분류 실패 시 사용자가 직접 카테고리 선택
- 영수증으로 분류된 경우 “영수증으로 분류된 문서가 있습니다.” 토스트 표시

### 4.2 AI 문서 분석

OCR과 LLM을 활용하여 문서 내용을 분석하고 핵심 정보를 추출합니다.

주요 기능:
- 문서 종류 자동 분류
- 만료일, 금액, 갱신일 등 핵심 데이터 추출
- 추출 결과를 JSON 형태로 저장
- 영수증 특화 파싱
  - 날짜
  - 가게명
  - 카테고리
  - 금액
  - 품목

분류 카테고리 예시:
- 계약서
- 임대차계약서
- 보험
- 보증서
- 처방전
- 청구서
- 증명서
- 신분증
- 기타
- 영수증

### 4.3 디지털 캐비닛

업로드된 일반 문서를 안전하게 보관하고 빠르게 검색할 수 있는 문서 보관함입니다.

주요 기능:
- 전체 문서 목록 조회
- 문서명, 태그, 카테고리, OCR 본문 검색
- Elasticsearch 기반 통합 검색
- 카테고리 필터
- 최신순, 이름순, 만료일순 정렬
- 카드형 / 리스트형 보기 전환
- 즐겨찾기
- 태그 관리
- 문서 상세보기
- 문서 다운로드
- 문서 삭제
- Pro 전용 PDF 병합 다운로드
- 문서를 PDF 형식으로 내려받기

검색 정책:
- 별도의 검색 페이지는 사용하지 않음
- 검색은 디지털 캐비닛 내부 검색창에서 처리
- 검색 결과는 현재 문서 목록에 바로 반영
- 검색 결과가 없을 경우 “검색 결과가 없습니다.” 표시

### 4.4 문서 상세보기

디지털 캐비닛에서 문서를 선택하면 원본 이미지와 AI 추출 정보를 함께 확인할 수 있습니다.

- 추출 정보 수정
- 알림 설정
- 태그 추가 및 수정
- 즐겨찾기
- 다운로드
- 공유
- 삭제

알림 기본값 예시:

- 임대차 계약서: 만기 6개월 전
- 기타 계약서: 만기 1개월 전

### 4.6 영수증 관리

영수증은 일반 문서와 동일한 업로드 입구를 사용하지만, AI 분석 결과 영수증으로 분류될 경우 디지털 캐비닛이 아닌 영수증 관리 페이지에서 별도로 관리합니다.

영수증 처리 정책:
- 업로드 입구는 일반 문서와 공통 사용
- AI 분석 결과 영수증으로 분류되면 영수증 관리 페이지에서 관리
- 일반 문서와 영수증은 조회 화면과 DB 테이블을 분리
- 원본 이미지 파일은 S3에 저장
- 영수증 분석 데이터는 `receipts` 테이블에 저장
- 영수증으로 분류된 경우 토스트 메시지 표시
- 사용자는 영수증 관리 페이지에서 상세 내역을 확인하고 수정 가능

주요 기능:
- 영수증 목록 조회
- 월별 지출 합계 표시
- 영수증 수 표시
- 최다 소비 카테고리 표시
- 전월 대비 증감률 표시
- 가맹점명, 메모, 결제 항목 검색
- 카테고리 필터
- 기간 필터
- 금액순 / 날짜순 정렬
- 영수증 상세 확인
- 영수증 업로드
- 수기 입력

검색 기준:
- 가맹점명
- 메모
- 결제 항목
- OCR 추출 텍스트

카테고리 예시:

## 5. 시스템 아키텍처

```txt
Web / Mobile App
        ↓
NestJS API Server
        ↓
PostgreSQL / Redis / S3
        ↓
Python Worker
        ↓
OCR / AI Extraction / Classifier / Scheduler
```

상세 흐름:
1. 사용자가 Web 또는 Mobile App에서 이미지 업로드
2. API 서버가 파일을 S3에 저장
3. Redis Queue에 분석 작업 등록
4. Python Worker가 OCR 및 AI 분석 수행
5. 분석 결과를 JSON으로 정리
6. 문서 종류에 따라 `documents` 또는 `receipts`에 저장
7. 만료일 또는 갱신일이 있는 문서는 알림 스케줄러에 등록
8. 사용자는 디지털 캐비닛, 영수증 관리, 소비 리포트에서 결과 확인

## 16. 확정된 사항

1. 업로드 지원 형식
   - 업로드는 JPG / PNG 이미지 파일만 지원합니다.
   - PDF는 업로드 형식으로 받지 않습니다.
   - 단, 사용자가 문서를 PDF 형식으로 내려받는 기능은 제공합니다.

2. 파일 용량 제한
   - 파일 용량은 장당 최대 10MB로 제한합니다.

3. Pro 플랜 가격
   - Pro 플랜 가격은 월 5,900원으로 설정합니다.

4. 업로드 플로우
   - Web 환경에서는 JPG / PNG 이미지 파일을 업로드합니다.
   - Mobile App 환경에서는 카메라를 직접 실행하여 촬영한 사진 파일을 업로드 대상으로 사용할 수 있습니다.
   - 업로드 후 OCR 및 AI 분석을 진행합니다.
   - 분석 결과 일반 문서는 디지털 캐비닛에 저장하고, 영수증은 영수증 관리 페이지에서 별도로 관리합니다.

5. 검색 페이지
   - 별도의 검색 페이지는 사용하지 않습니다.
   - 검색 기능은 디지털 캐비닛 내부 검색창에서 처리합니다.
   - 검색 결과는 현재 문서 목록에 바로 반영합니다.

6. Cognito
   - 현재 단계에서 Cognito 사용 여부는 확정하지 않습니다.
   - 추후 인증 구조 확장 시 활용 가능성이 있는 기술로 남겨둡니다.

7. 영수증 처리 방식
   - 업로드 입구는 일반 문서와 동일하게 사용합니다.
   - AI 분석 결과 영수증으로 분류될 경우 디지털 캐비닛이 아닌 영수증 관리 페이지에서 별도로 관리합니다.
   - 일반 문서 데이터는 `documents` 테이블에 저장합니다.
   - 영수증 데이터는 `receipts` 테이블에 저장합니다.
   - 원본 이미지 파일은 공통으로 S3에 저장합니다.

## 17. 추가 확인이 필요한 사항

1. AI 예상 지출 데이터
   - 소비 리포트의 예상 지출은 어떤 기준과 데이터로 산출할지 논의가 필요합니다.

2. 카드 추천 기능
   - 카드 추천은 Pro 기능으로 표시되어 있으나, 실제 카드 데이터 수집 방식과 추천 기준 확정이 필요합니다.

3. 마스킹 기능 범위
   - Pro 기능으로 표시되어 있으나, 자동 마스킹인지 사용자가 직접 영역을 지정하는 방식인지 확정이 필요합니다.

4. Cognito 도입 시점
   - 자체 인증으로 먼저 구현할지, 초기부터 Cognito를 고려한 구조로 설계할지 추가 논의가 필요합니다.
